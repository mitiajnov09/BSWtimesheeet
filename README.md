# BSW ROTACIJA · BETA testing

Веб-приложение для планирования ротаций строительных и производственных команд. Python 3.12, SQLite, интерфейс без сборщика JavaScript. Языки: русский, литовский и польский. Один сервер обслуживает пользователей и хранит общую базу.

**[Последние изменения → CHANGELOG.md](CHANGELOG.md)**

**[Проверки и ограничения → TEST_REPORT.md](TEST_REPORT.md)**

## Возможности

- Проекты, объекты, назначения работников, команды и кадровые отметки TL/WM.
- Календарь по месяцам, кварталам и годам; недели в формате W43; ежедневная численность работающих на объекте.
- Рабочие циклы, отдых, отпуск и больничный; ручные исключения и дополнительные слои.
- Короткий клик открывает форму; движение зажатой полосы и её краёв сохраняет даты без формы. Проверки пересечений и версий выполняются сервером.
- Поездка занимает день: самолёт, машина или паром. В день поездки работник исключён из числа работающих на объекте.
- Круглые фотографии работников в интерфейсе и PDF. Экспорт A4/A3 с фото или без, с примечаниями и событиями.
- Фирменное оформление BSW, светлая/тёмная тема, метка BETA testing.
- Кнопка обратной связи: текст и скриншот. Раздел «Отзывы» и просмотр вложений доступны только администратору.
- История изменений, защита от одновременного сохранения устаревших записей, сессии и смена пароля.

## Доступ

| Роль | Возможности |
| --- | --- |
| Администратор | Пользователи, проекты, работники, команды, весь график, фотографии и отзывы |
| Руководитель проекта | Назначенные проекты, график, поездки и PDF; отправка обратной связи |
| Секретарь | Назначенные проекты; отдельные периоды работы/больничного и поездки; PDF и обратная связь |
| Работник | Только кадровая запись; учётной записи и входа в систему нет |

Администратор создаёт учётные записи руководителей и секретарей, затем назначает их проекту. TL/WM — кадровые отметки работников, они не предоставляют доступ.

## Быстрый локальный запуск

Установите Python 3.12. Команды для macOS/Linux:

```sh
git clone https://github.com/mitiajnov09/BSWtimesheeet.git
cd BSWtimesheeet
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
.venv/bin/python app.py --create-admin admin
.venv/bin/python app.py
```

Пароль вводится дважды скрыто; минимум 10 символов. Откройте http://127.0.0.1:8080. Структура SQLite создаётся автоматически. Для новой рабочей базы не используйте `--demo`.

Если нужна демонстрация, вместо `--create-admin` выполните `app.py --demo` **один раз в пустой базе**. Демонстрационные пароли случайные и сохраняются только локально в `data/demo-credentials.txt`. В репозитории нет готового пароля или рабочей базы.

Для Windows используйте `.venv\Scripts\python.exe` вместо `.venv/bin/python` и создайте `.env` копированием `.env.example`.

## База данных

SQLite не требует установки PostgreSQL/MySQL или отдельного сервера БД. `app.py --migrate` создаёт файл и применяет миграции 001–007. Путь задаётся через `APP_DB`. Повторные миграции безопасны; данные сохраняются.

В базе находятся пользователи, назначения, график, история, фотографии и отзывы со скриншотами. Используйте постоянный локальный диск либо Docker-том. `.env`, базы, резервные копии и локальные пароли исключены из Git и Docker-образа.

## Маленький скрипт резервного копирования

Скрипт использует только стандартную библиотеку Python; отдельные зависимости не нужны. Он работает при запущенном приложении и корректно включает изменения из WAL.

```sh
.venv/bin/python backup.py
```

Копия появится в `backups/bsw-rotacija-ДАТА.sqlite3`. Можно указать имя и исходную базу:

```sh
python3 backup.py backups/manual.sqlite3 --database /path/to/rotations.sqlite3
```

Для Docker:

```sh
./scripts/backup-docker.sh
```

Восстановление выполняется **при остановленном приложении**:

```sh
.venv/bin/python restore.py backups/ИМЯ-КОПИИ.sqlite3 --replace
.venv/bin/python app.py --migrate
```

Перед заменой существующей базы сохраните её отдельную копию. Полные команды восстановления, ежедневного копирования и обновления описаны в [DEPLOYMENT.md](DEPLOYMENT.md).

## Проверки

```sh
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
node tests/test_i18n.cjs
node tests/test_palette.cjs
node tests/test_roles_ui.cjs
node tests/test_drag.cjs
```

Node.js нужен для проверок JavaScript, но не для работы приложения. После редактирования переводов выполните `node scripts/sync-translations.cjs`.

PDF проверен через рендеринг. Браузерные действия в этой среде не проверены: инструмент отклонил локальный адрес. Docker и настоящий сервер здесь не запускались, поскольку Docker и доступ к серверу отсутствуют. Эти ограничения подробно отражены в TEST_REPORT.md.
