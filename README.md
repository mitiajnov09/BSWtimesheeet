# Ротации

Рабочая локальная версия приложения для строительных и производственных проектов. Интерфейс на русском языке; сервер проверяет доступ к данным, изменениям и PDF. Публикация не выполнялась.

## Открыть текущую версию

Сервер разработки запущен по адресу **http://127.0.0.1:8080**. Входите по логину `admin`; случайный пароль записан в `data/demo-credentials.txt`. Там же находятся логины `manager` (только Стокгольм) и `other` (только Берлин). Файл содержит демонстрационные секреты, доступен владельцу и исключён из Git. Не переносите его и демонстрационную базу в рабочую среду.

Стокгольм содержит 10 вымышленных работников, циклы с разными датами начала, перелёты, отпуск и больничный. Берлин содержит отдельного работника для проверки доступа.

## Обычный запуск на своём компьютере

Нужны Python 3.12 и интернет только для первой установки библиотеки PDF.

```sh
cd /path/to/timesheet
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
.venv/bin/python app.py --demo
.venv/bin/python app.py
```

`--demo` выполняют один раз в пустой базе. При последующих запусках используйте только `python app.py`. Если база уже существует, она не перезаписывается. Откройте http://127.0.0.1:8080 в браузере.

В текущей среде Codex установка не нужна: используйте `/Users/mitiajnov/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 app.py` из папки проекта.

## Рабочая база и первый администратор

SQLite — настоящая файловая база данных, подходящая для одного сервера и небольшой команды руководителей. Расположите её на постоянном локальном диске. Не размещайте файл на сетевом диске, в общей папке синхронизации или в нескольких независимых контейнерах.

1. Остановите приложение перед изменением настроек.
2. Скопируйте `.env.example` в `.env` и задайте `APP_DB=/absolute/path/rotations-production.sqlite3`. Выберите новый пустой файл вместо демонстрационного.
3. Выполните `python app.py --migrate` — создаст структуру базы.
4. Выполните `python app.py --create-admin admin` — пароль вводится скрыто в терминале, не в исходном коде.
5. Запустите приложение. Администратор создаёт объекты, проекты, работников и руководителей; в карточке проекта выбирает руководителей, затем назначает работников с датами.
6. Пароль меняется через меню пользователя. Смена пароля завершает все его сессии.

Список миграций находится в `migrations/`. Применённые номера хранятся в базе, повторный запуск безопасен. Входные учётные записи не создаются автоматически в рабочей базе.

## Как пользоваться графиком

Выберите проект, месяц, квартал или год. Календарь прокручивается по горизонтали; имена и заголовки закреплены. Доступны поиск по имени и специальности, фильтры специальности и статуса, кнопки предыдущего/следующего периода и «Сегодня».

«Запланировать» строит индивидуальный цикл. В меню «…» у работника можно построить цикл, добавить отдельный период или событие. Нажатие на полосу открывает её форму. Перетаскивание полосы или её края предлагает новые даты в форме; сохранение применяется после нажатия кнопки. Это даёт возможность выбрать область изменения и проверить даты. Для сдвига следующих автоматических периодов длительность выбранного периода должна остаться прежней. Ручные исключения при этом остаются на прежних датах; конфликт прерывает сохранение.

Даты начала и окончания включаются в период. По умолчанию 6/2 = 42 календарных дня работы и 14 дней отдыха. Календарные выходные показаны фоном; они не отменяют рабочую ротацию. Каждый основной период относится к одному проекту. Пересечения внутри проекта разрешены на разных слоях. Внутри одного слоя и между разными проектами пересечения запрещены.

Перед заменой автоматических периодов показывается предпросмотр. Ручные правки сохраняются на своих датах: новые автоматические полосы разделяются вокруг них. Части прежнего графика за пределами выбранного диапазона сохраняются. Чтобы убрать исключение, удалите его вручную, затем снова постройте цикл. Новый ручной период поверх существующего получает первый свободный слой. График автоматически увеличивает высоту строки, а PDF показывает все слои. Автоматический цикл перестраивает основной слой; дополнительные ручные слои остаются без изменения.

Назначения на разные объекты не пересекаются. На один объект допускаются назначения на разные проекты, однако основной статус работника всё равно единственный. Даты назначения должны охватывать ротации и события. Архивирование сохраняет все исторические записи и запрещает дальнейшее редактирование до восстановления.

Перелёты — отдельный слой. Они могут совпадать с любым основным статусом. Время хранится и показывается с именем часового пояса IANA, например `Europe/Stockholm`.

## PDF

Кнопка «Экспорт в PDF» позволяет выбрать проект, даты, работников, A4/A3 и включение примечаний/перелётов. Сервер проверяет доступ и выбранных работников. Экспорт охватывает весь диапазон до пяти лет независимо от прокрутки экрана. На A4 по 28 дней на странице, на A3 по 42; большие команды также разбиваются по строкам. Повторяются имена, месяцы, ISO-недели, дни и легенда. Буквы Р/О/У/Б и звёздочка ручной правки помогают читать чёрно-белую распечатку. События обозначены буквами, полные сведения и примечания вынесены в приложение. Используется встроенный шрифт с кириллицей.

Пример годового PDF: `output/pdf/stockholm-2026.pdf`.

## Будущее размещение, домен и HTTPS

Развёртывание пока **не выполнялось**. Для него понадобится один Linux-сервер с постоянным диском, Docker Compose, домен и доступ к DNS. Сервер и домен могут быть платными; выбор и расходы обсуждаются перед размещением. Приложение не рассчитано на статический хостинг или Cloudflare Workers без переноса серверной части. Подключение PostgreSQL потребует отдельного адаптера и миграции; текущая рабочая база — SQLite.

После отдельного указания на публикацию:

1. Скопируйте исходники на сервер, исключая `data/`, `.env`, `output/` и локальные демонстрационные пароли.
2. Скопируйте `deploy/.env.production.example` в `.env`. Укажите свой домен в `APP_DOMAIN`.
3. Направьте DNS-запись A на IP сервера (AAAA только если IPv6 настроен), откройте входящие TCP 80 и 443. Не открывайте порт приложения 8080 в интернет.
4. Выполните `docker compose build`.
5. Подготовьте каталог копий: `mkdir -p backups && sudo chown 10001:10001 backups && chmod 700 backups`.
6. Создайте первого администратора: `docker compose run --rm app python app.py --create-admin admin`.
7. Запустите `docker compose up -d`. Caddy автоматически выдаст и обновит сертификат HTTPS после корректного DNS. Cookie станет Secure, разрешённый источник запросов — выбранный домен.
8. Проверьте вход, создание/сохранение графика, повторный вход, ограничения руководителей и скачивание PDF по доменному адресу. Смените начальный пароль через интерфейс.

Сервер запускается без административных прав внутри контейнера. Данные находятся в постоянном Docker-томе `rotations_data`. `docker compose down` сохраняет том; **не применяйте `down -v`**, это удаляет данные. Версии образов и конфигурацию хостинга уточним и проверим при реальном размещении. Docker-конфигурация пока не проверялась запуском контейнеров.

## Резервное копирование и восстановление

Нельзя просто копировать открытый SQLite-файл: часть данных может находиться в WAL. Скрипт использует штатный механизм SQLite Backup и проверяет целостность.

Локально:

```sh
python backup.py backups/rotations-2026-10-06.sqlite3
```

В Docker:

```sh
docker compose exec app python backup.py /backups/rotations-2026-10-06.sqlite3
```

Для регулярного копирования настройте ежедневный запуск этой команды с уникальной датой имени. Храните, например, 30 ежедневных копий и ежемесячные копии отдельно от сервера. Они содержат данные сотрудников и хеши паролей: ограничьте доступ, шифруйте при переносе. Периодически проверяйте восстановление в отдельной базе.

Восстановление локальной версии:

1. Остановите приложение.
2. Сохраните резервную копию текущей базы. Если её нужно сохранить при повреждении, перенесите существующий файл **вместе с** `-wal` и `-shm` в отдельную папку.
3. Положите выбранную согласованную копию по пути `APP_DB`. Удалите/перенесите старые `-wal` и `-shm` перед первым открытием восстановленной базы.
4. Выполните `python app.py --migrate` и запустите сервер. Проверьте вход и последние ротации.

В Docker остановите приложение (`docker compose stop app`), создайте копию через `docker compose run --rm app python backup.py /backups/before-restore.sqlite3`, затем восстановите файл **в остановленный том**:

```sh
docker compose run --rm app python -c "import sqlite3; s=sqlite3.connect('file:/backups/rotations-2026-10-06.sqlite3?mode=ro', uri=True); assert s.execute('PRAGMA integrity_check').fetchone()[0]=='ok'; d=sqlite3.connect('/app/data/rotations.sqlite3'); s.backup(d); d.close(); s.close()"
docker compose up -d app
```

Дату копии замените своей. SQLite Backup корректно заменяет базу и обслуживает WAL; контейнер приложения при этом должен быть остановлен.

## Обновление без потери данных

Перед обновлением создайте копию. Заменяйте исходники/образ, сохраняя `.env`, путь SQLite и постоянный том. Локально: остановить сервер → обновить зависимости → `python app.py --migrate` → запустить. В Docker: `docker compose build` → `docker compose stop app` → `docker compose run --rm app python app.py --migrate` → `docker compose up -d`. При несовместимой миграции откат — старый образ плюс резервная копия соответствующей версии базы. Не удаляйте том.

## Проверки и ограничения первой версии

`python -m unittest discover -s tests -v` запускает проверки доменной логики и настоящего HTTP API на отдельной временной базе. Для тестов PDF дополнительно установите `pypdf`. В текущей среде Codex он доступен. Результаты: `TEST_REPORT.md`.

Данные сохраняются в SQLite; обновление страницы и повторный вход не меняют их. Конкурентные изменения проверяются по версии записи и версии графика работника под блокировкой транзакции. Устаревшее сохранение отклоняется с понятным сообщением и предложением обновить данные. Автоматического объединения конфликтующих правок и живого обновления чужих изменений пока нет; кнопка обновления загружает свежую версию.

Браузерная проверка интерфейса и переноса мышью пока не выполнена: инструмент браузера отклонил доступ к локальному адресу. Визуальная проверка PDF и серверные тесты выполняются отдельно. Настоящее размещение, HTTPS и контейнеры ещё не проверены. Перед рабочим запуском нужны проверка интерфейса, реального восстановления копии на выбранном сервере и согласование правил эксплуатации. Первый этап предназначен для просмотра и ваших корректировок.


## Обновление: языки, перетаскивание из легенды и неактивные работники

Выберите русский, литовский или польский язык в правом верхнем углу или на странице входа. Выбор сохраняется в этом браузере. PDF использует выбранный язык. Сохранённые имена, названия проектов, специальности и примечания не переводятся автоматически.

Перетащите «Работа», «Отдых», «Отпуск», «Больничный» или значок перелёта из нижней легенды на нужный день в строке работника. Во время переноса подсвечивается день. Создаётся запись на один день; нажмите на неё, чтобы изменить даты или сведения о перелёте. Если выбранный диапазон уже занят, новая полоса сохраняется на первом свободном дополнительном слое. Можно также нажать значок в легенде, затем свободное место нужного дня. Добавление доступно только активным работникам в активных проектах.

Администратор может выбрать «Удалить из списка» в разделе работников или меню «…» графика. Это делает работника неактивным, сохраняет назначения, график и историю. В фильтре «Неактивные работники» доступна кнопка «Вернуть в список». По умолчанию показываются активные работники.

Миграция `002_period_layers.sql` добавляет слои существующим записям без изменения дат. Перед миграцией текущей локальной базы создана копия `data/before-layers-2026-10-06.sqlite3`.

Переводы: `static/i18n.js`; после изменения словаря выполните `node scripts/sync-translations.cjs`, чтобы обновить словарь серверного PDF. Проверки переводов: `node tests/test_i18n.cjs`; проверки расчёта дня и сохранения из палитры: `node tests/test_palette.cjs`.

## Учётные записи руководителей и секретарей, команды проекта

Работники — только карточки кадрового списка. Добавление работника **не создаёт учётную запись** и не даёт доступа к системе.

Администратор нажимает «Создать учётную запись» над графиком или «Учётные записи → Добавить пользователя», вводит имя, логин и пароль и выбирает роль «Руководитель проекта» или «Секретарь». Затем в карточке проекта в поле «Руководители и секретари» отмечает пользователей, которым нужен доступ. Один пользователь может иметь несколько проектов. Отключение пользователя или изменение его роли завершает существующие сессии.

Секретарь видит только назначенные проекты и их работников. Он может создавать, редактировать и удалять отдельные рабочие периоды, больничные и перелёты. Для отпуска, отдыха, остальных событий и массового изменения циклов доступ только на просмотр. Создание/изменение/отключение пользователей, карточек работников, проектов, назначений и команд секретарю запрещены на сервере. Смена собственного пароля доступна всем вошедшим пользователям.

Администратор создаёт команду кнопкой «Команда» в графике или карточке проекта. В форме выбираются название и работники проекта. У работника одна команда в каждом проекте; выбор в другой команде переносит его туда. В меню работника «… → Команда работника» можно изменить команду или выбрать «Без команды». График по умолчанию группируется по командам; флажок «По командам» отключает группировку. Команды можно переименовывать; изменения состава фиксируются в истории и защищены версиями от одновременных правок.

Миграция `003_secretaries_and_teams.sql` расширяет роли, сохраняя существующие учётные записи, пароли, сессии и связи. Перед её применением создана копия `data/before-secretaries-and-teams-2026-10-06.sqlite3`.

## Команды, ежедневная численность и оформление

Пустые активные команды отображаются в графике при включённой группировке «По командам». Кнопка «+» в заголовке команды открывает её состав. При создании команды используется открытый проект, без повторного выбора проекта.

Удаление команды предлагает два варианта: оставить работников на объекте либо убрать их из текущего проекта. Во втором случае назначения становятся неактивными только в этом проекте. Карточки работников, периоды и история сохраняются в обоих случаях. Команда архивируется.

Добавлять работников на объект можно внутри открытого проекта кнопкой «Добавить работника» над графиком: выбрать существующую карточку или создать новую. На странице проектов такой кнопки больше нет.

Под каждой датой показано количество активных работников с действующим назначением и статусом «Работа». При пересечении слоёв учитывается верхний слой: больничный, отпуск или отдых исключает человека из числа работающих. Поиск и фильтры строк не меняют общую численность объекта.

В карточке работника поле «Роль работника» позволяет выбрать Team Leader или Work Manager. Рядом с именем отображается TL или WM. Это кадровые отметки, они не создают учётных записей и не предоставляют доступ.

Кнопка солнца/луны переключает светлую и тёмную темы на странице входа и в приложении. Выбор сохраняется в браузере. Имена всех 11 текущих работников заменены на литовские с сохранением их идентификаторов и связей.

Миграция `004_team_lifecycle_and_leadership.sql` добавляет состояние команды, активность назначения и кадровую роль. Перед обновлением сохранена копия `data/before-teams-theme-2026-10-06.sqlite3`.
